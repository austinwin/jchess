# JChess Academy ♞

**A child-first, family-private chess academy** with colorful missions and a live parent view. Built with **QPyServe + FastAPI + Vite/React**, deployable as one Render web service with PostgreSQL.

## What works

- A responsive, animated chessboard with drag-and-drop and click-to-move.
- Six training categories, including strategic planning.
- **14 guided lessons** covering forks, pins, skewers, discovered attacks, double attacks, removing defenders, back-rank mates, center control, development, castling, pawn breaks, passed pawns, rook files and piece activity.
- Each lesson teaches a short checklist and opens legally validated practice boards. New lessons are backfilled into existing databases without deleting progress.
- Hundreds of generated, legally validated built-in exercises; a streaming import tool can add thousands of **official CC0 Lichess puzzles**.
- Automatic difficulty targeting and recycling previously completed material.
- Parent/child accounts and family-scoped authorization.
- **Live view**: parents see the child's current board, puzzle, attempts, opponent responses and progress. The parent page refreshes every 1.8 seconds.
- **Parent-only answer keys**, animated move-by-move solution replay, and an explicit switch to reveal the solution on the child's screen.
- Server-side move legality and answer validation with python-chess.
- Optional parent-supplied OpenAI API key, encrypted at rest, for a manually requested performance-based coaching report. It stays OFF by default. Only aggregate category statistics leave the server. Parents can choose 1–10 requests per day (enforced in PostgreSQL), disable AI, replace or delete the key. The browser never receives the stored key.

## Local development

Requires Python 3.10+, Node 20+ and npm.

```bash
python -m pip install -r requirements.txt
cd frontend && npm install && cd ..
DEMO_USERS=true python main.py
```

Visit **http://localhost:1111**. Demo accounts are available **only outside Render**:
- Parent: `hoang / hoang`
- Child: `justin / justin`

Both must change their passwords upon first login. **Never expose these passwords to the public internet.**

## Deploy on Render

The repository includes a multi-stage Dockerfile and `render.yaml` Blueprint for a web service and persistent PostgreSQL. QPyServe serves the built Vite app and FastAPI at the **same origin**. This prevents needing a separate frontend URL or cross-origin cookies.

1. Select the intended Render workspace and create a Blueprint from this repository on the `main` branch.
2. Review the Blueprint plan **and pricing** before approving. A free Postgres database may have limited lifetime; use an appropriate durable plan for ongoing progress storage.
3. The existing JChess Blueprint provisions the `hoang` parent and `justin` child using one-time salted password hashes. Both users must change passwords at first login. Never commit a plaintext API key or account password. Keep `DEMO_USERS=false` in production.
4. Existing users are never overwritten when the service restarts. New parents can add other children in **Children**.
5. `AI_ENCRYPTION_KEY` is generated by Render. Keep it stable to preserve access to stored API keys.
6. Render auto-deploys changes when the service/Blueprint is connected to GitHub.

**Why not deploy `justin/justin` and `hoang/hoang` publicly?** Anyone who sees the public URL could sign in as either child or parent before a password change. Demo credentials only run locally; production is intentionally protected.

## Import thousands of verified Lichess puzzles

```bash
python -m scripts.import_lichess --limit 2000 --offset 100000
```

The importer retrieves bounded 100-puzzle batches from the public Lichess dataset via Hugging Face, filters ratings between 550–1500 and checks every legal move. It **applies the first opponent move to the FEN before showing the exercise**, as specified in Lichess's data documentation. Import in the same environment/database as the app, or integrate it with a controlled admin job. This is an optional network-dependent import; core exercises work offline.

Source: https://database.lichess.org/#puzzles (CC0).

## Important behavior and limitations

- This release focuses on puzzle solving and family viewing. The free-play board accepts legal moves for **both colors**, and is not a chess engine opponent.
- This release uses 1.8-second polling, not WebSockets. It works across multiple web processes sharing PostgreSQL.
- Parents see solution UCI moves and an animation. Child accounts cannot fetch answer keys unless a connected parent enables reveal.
- The guided curriculum includes original pin, skewer, discovered attack, back-rank and strategic model-move positions, in addition to automatically generated drills. Optional CC0 Lichess imports offer much larger tactical variety. A strategic model move is an illustration, not the only good chess move.
- Default first-try scores count exercises finished without any incorrect move.
- AI coaching is not a source of truth for legal chess positions; the deterministic chess rules engine is. Parents control when the API is called and the daily report limit.
- JChess stores encrypted keys in the `ai_config` database table, usage limits in `ai_usage`, and never persists reports, names, or raw game history to the AI provider. Read [AI key security and data flow](docs/AI_SECURITY.md).
- For a second child or parent, create a new account. Linking additional parents to an existing child requires a future invitation and approval flow rather than an unsafe public lookup.
- Browser cookies are HttpOnly and Secure on Render; passwords are salted PBKDF2 hashes. Protect `DATABASE_URL`, `BOOTSTRAP_ADMIN_PASSWORD` and `AI_ENCRYPTION_KEY`.
